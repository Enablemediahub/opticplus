DATABASE SETUP (run once in Hostinger phpMyAdmin; do not FTP this SQL file)
Open database/manual_sql/create_push_subscriptions.sql from the package, select the
Hostinger database, and run the SQL in phpMyAdmin's SQL tab. This creates the table
needed for phone push subscriptions. It intentionally has no foreign key to the legacy
users table, avoiding Hostinger schema/engine mismatches. Do not run it a second time
after the table exists. The equivalent Laravel migration is in the backend source for
environments that use Artisan migrations.

SERVER SETUP (not files to upload)
1. In a trusted server terminal, run: php artisan webpush:generate-vapid
2. Add the generated WEBPUSH_PUBLIC_KEY and WEBPUSH_PRIVATE_KEY to the server .env.
   Also set WEBPUSH_SUBJECT to a valid mailto: address or the portal URL.
   Never upload, commit, or share the private key.
3. Use Hostinger SSH/Terminal to run: php artisan config:clear
   (if SSH/Terminal is unavailable, check with Hostinger support how to clear Laravel's
   cached configuration; changing .env alone does not update a cached config.)
4. Ensure the portal is served over HTTPS. Managers enable notifications from their account
   on each phone/browser, and must allow notifications in the device/browser settings.

In-app counts and slide-in notifications do not require VAPID keys. Phone push and app-icon
badges depend on browser/operating-system support.
